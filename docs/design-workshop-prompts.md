# Four Hearts 页面分模块共创提示词

这份提示词用来让接手的前端 Agent 与 Olivia 逐块调研和共创原型。它不是一键生成整站的指令。每次只复制“共通母提示词”加一个模块提示词。

## 使用顺序

1. 先跑模块 01：四叶轮表面质感与旋转/进入反馈。
2. 评估调研结果和 A/B/C 原型；选中一版后，再进入模块 02。
3. 后续每次只打开一个模块。未经 Olivia 选定的原型，不合并进正式页面。

## 共通母提示词（每个模块都要附上）

你是 Olivia 的设计研究与前端原型搭档，不是收到一句话就一次性输出成品的代码生成器。本轮只研究和共创一个模块；不要顺手改其他页面，不要直接改正式实现。

### 先做现状走查
- 先检查当前代码、依赖、页面状态、相关组件和响应式规则。引用真实文件路径与具体实现，不要让用户重复描述代码里已经能看到的内容。
- 记录当前交互、已有视觉约束、已确认的决定、明显的技术债和这次不能破坏的行为。
- 项目当前主要栈是 React 19、TypeScript、Vite、Three.js、React Three Fiber、Drei 与 postprocessing。以 package.json 和当前实现为准；不要只凭这句话选库。

### 再做技术调研
- 至少找 3–5 个可核查参考：优先真实开源仓库和可运行 Demo，其次官方文档、技术文章；如 X/Twitter 上有相关实现或 prompt 帖，也可作为灵感来源。
- 对每个来源给出直达链接、作者/维护方、发布时间或最后更新日期、具体值得看的实现点。检查源代码和许可证；不要只摘营销文案或截图。
- X/Twitter 帖子只当设计灵感，不把帖子里的断言当技术事实。技术结论要用代码、官方文档或可复现 Demo 交叉验证。找不到可靠来源时明确写“未找到”，不要编链接。
- 比较：复用当前实现、引入现成库、自己实现。评估维护状态、许可证、包体、性能、浏览器支持、可访问性、减少动态效果和技术债。
- 先研究再建议引擎/库。能复用现有 React/SVG/CSS/Three.js 实现时，不为效果而加依赖；只有证据表明现有工具做不到时才推荐第三方。

### 研究之后，和用户一起抽原型
- 给出 2–3 个可区分的视觉/交互方向，每个方向写清：看起来怎样、如何操作、技术实现路线、优缺点和风险。
- 用低保真线框、独立 HTML/本地预览或可比较的静态样稿表达，不要把 A/B/C 混进正式页面。用户提出的参考图要说明借鉴了哪个具体细节。
- 让 Olivia 先选一个方向或要求组合；一次只问一个会改变结果的问题。用户没选之前，不做正式改造。
- 用户选定后，再做该模块的可点原型给她试手感；按反馈继续迭代。明确收到“合并/执行”前，不改正式产品代码、不装依赖、不推送。

### 每轮交付格式
1. 现状和约束（文件路径）。
2. 调研来源与证据链接。
3. 方案比较表（复用 / 第三方 / 自研）。
4. A/B/C 原型卡或可点预览入口。
5. 潜在技术债、性能与可访问性检查。
6. 一个具体问题，等待用户选择。
7. 用户选定后给出实施范围和回滚边界。

## 模块 01：四叶轮质感、引导与进入过渡

检查 study/src/brand/Heartwheel.tsx、Heartwheel.css、study/src/ui/LeafCanvas.tsx、LeafCanvas.css 和实际页面状态。保持四片叶子的几何结构、已确认的颜色分配和原有导航逻辑；不要重新造一个轮盘。

研究 SVG 滤镜/纸张纹理、分层 CSS、Canvas/WebGL shader、Three.js 粒子/弥散等路径，重点判断哪种方式能与白底 loading page 的留白和微小粒子风格自然衔接。用户想讨论叶轮停驻章节里的 hover 旋转、滚动时联动、点击时同步旋转，以及进入下一页时更柔和的弥散。只在这块停驻章节触发，不让全页滚动都带动轮盘，不让装饰动画妨碍点击和阅读。

先提出 2–3 种材质/运动样稿：例如细腻纸纤维、半透明彩色薄片、轻颗粒组装；颜色沿用既定色系。检查方向提示是否让人知道四片叶子都可点，不再让右侧叶片看起来像唯一入口。评估 SVG/CSS 和 Three.js 的成本、移动端性能与 reduced-motion 行为，再做可比较的独立样稿。

## 模块 02：Index 的 Quick Read 三张实体卡

检查 QuickRead.tsx、QuickRead.css、Archive.tsx 和对应响应式规则。Quick Read 分实习、教育、精选作品；卡片高度必须一致，三张分别有自己的主题内容与入口，不能因文字行数不同而底边错位。用户不喜欢泛黄的 AI 模板感，也不想再叠多层线框。

先调研 React Bits 中真实可运行的卡片交互，以及成熟的纸张/票据/文件夹 UI 实现。比较细腻的纸纹、压印、轻微倾斜、翻页/抽拉等方向，但不要先决定必须做成某一种。给出 2–3 个视觉样稿，说明卡片正面承载什么、点击后去哪、三张如何保持同高，以及触屏上如何操作。平衡实体感和作品集内容的清晰度，避免材质抢走标题。

## 模块 03：右上角实体折页

检查 study/src/PageTurn.css、相关 PageTurn 组件和当前角标点击逻辑。参考 Olivia 已给的 Ryos 仓库与文章：
- https://github.com/ryokun6/ryos
- https://ryo.lu/journal/when-we-can-do-anything

先读代码和许可证，拆解纸角曲率、纸张反面、折线、投影和交互命中区。比较 CSS 3D、SVG 路径/滤镜、Canvas/WebGL 等可复用路径。目标是有弧度、有纸背和受光的真实折角，不接受仅把三角形换颜色。保持现有导航结果和按钮可访问性。先做三种可比较的小折角原型，不直接替换线上角标。

## 模块 04：Quick Read 实习工牌的真实弹性手感

检查 study/src/ui/ExperienceBadgeScene.tsx、QuickReadPage.tsx、QuickReadPage.css。当前已有 React Three Fiber 工牌场景与基础摆动；先找出它用了什么运动模型，避免重写已有实现。

调研真实吊牌/挂绳的钟摆、弹簧阻尼、拖拽释放惯性；比较用现有 R3F 自定义动力学、现有依赖，以及 Rapier 等现成物理引擎的成本。不要为了“真实”把简单交互做成重型模拟。原型需要能轻碰、拖动、松手回弹，速度逐渐衰减；摆幅、卡片重量、挂绳拉力有层次。检查三张卡相互遮挡、触屏误触、帧率、键盘替代操作和 reduced-motion。先做手感 A/B/C，不先改三张正式工牌资料。

## 模块 05：全局响应式与导航对齐

整体方向已批准：681–900px 使用紧凑并列布局，680px 以下收为紧凑单栏；本轮只调研和共创具体断点、对齐及节奏，不重开方向。

检查 ArchiveResume.css、LeafCanvas.css、QuickRead.css、QuickReadPage.css 以及 header 的实际 DOM。问题包括窄屏时导航不居中、断点之间布局互相打架、首屏四叶轮只露出一部分、Quick Read 三卡高度不齐。

对 320、360、390、430、600、768、900、1024、1280、1440 CSS px 走查，补充短视口、安全区、中文/英文文案和 125% 缩放场景。先找出每个断点的冲突来源，再比较：CSS Grid/Flex 流式布局、导航折叠、滚动导航等方案。原型要展示窄屏头部如何稳定居中、Hero/四叶轮层级、卡片同高和自然滚动；不要把所有内容硬塞进一个首屏，也不要只用缩小字体掩盖问题。

## 模块 06：全部项目目录的视觉重构

检查 Archive.tsx、ArchiveResume.css、library.ts 和每个项目实际可用的封面/媒体。现状问题是项目区过于单调、“线框套线框”，但全部项目必须继续可查、可读、可打开。

先调研编辑型作品集、项目档案、数字展签、图像目录等开源/可运行实现。提出 2–3 个不依赖重复描边卡片的内容组织原型，例如编辑目录、图像索引、策展式分组；这只是探索方向，不是预设答案。每个原型要说明 12 个项目如何分类、封面缺失怎么办、移动端如何浏览、如何从入口到详情。不要删项目、编造封面或项目内容。

## 模块 07：全站项目命名与内容来源核对

先从 GitHub 仓库主页、README 标题、当前 library.ts 和用户确认的信息建立一张 canonical registry。严格保留大小写、空格、连字符、重音符号；仓库名是技术标识，README 标题是项目展示名，两者冲突时明确列出并问 Olivia，不自行改写。

已核对的重点：
- Sown-Shaped 仓库 README 标题是 Sown & Shaped，不是 So Shaped。
- gama-QGIS 是仓库的准确大小写；根 README 说仓库含“两个课程项目”，需确认作品集展示名，不能改成 Gamma。
- Psychologist-Cafe 仓库 README 标题是“在场 · Philosopher's Café”，不是臆造的 Psychologist Café；Café 保留重音符号。
- 张枣诗歌研究仓库是 zhangzao，README 标题《镜子的两面》；不要写成“张导”，不要误用 zhang-zao。
- healther 仓库 README 使用 Healther；这是当前正式拼写，不擅自纠成 Healthier。

其他 README 标题也要逐个核对：bioaz-agent-workbench、knockknock、qiaopi、peekaboo、zhenru-temple、glass-aha、cat-meow-gallery。交付差异表：仓库 slug / README 展示标题 / 当前网页标题 / 建议 / 需用户决定项。不要批量改名，先让用户确认 canonical registry。

## 模块 08：3D Room 手机社交卡片

整体方向已批准：三张独立卡片、正面 SVG 插画、点按翻到各自原比例二维码；本轮只调研翻牌技术和可扫性，不重开卡片形式。

检查 PhonePanel.tsx、data/links.ts 和给定的三张码。三张卡分别对应公众号、小红书、网易云；每张正面是为平台设计的 SVG 纸艺插画，点击后翻到背面显示对应的原二维码。二维码按原比例完整展示、不裁切、不压装饰。研究 CSS 3D 翻牌与现成 motion 库的收益和触屏/减少动态效果支持；给出两种卡片排布原型后再让用户选。没有真实深链接时不要伪造“打开 App”链接。

## 模块 09：全局按钮、Logo 与视觉层级规范

盘点当前按钮尺寸、圆角/倒角、字号、图标比例、焦点态、hover/active 动画与 logo 四瓣几何；先从 CSS tokens 和组件用法找出既有规范及重复覆盖。用户以前提到“全局 8 层”，先查清它在代码或设计语境里具体指什么，不猜这八层是什么。

研究可复用设计系统/组件规范的实现案例，给 2–3 个可视 token/组件样稿，再确定统一规则。尤其确保快捷返回、back、关闭和窗口控制使用同一套按钮尺寸与图标笔画，不只统一首页。

## 模块 10：3D Room Macintosh 与模型走查

检查 LaptopDesktop.tsx/CSS、Macintosh 壁纸及 3D 场景对应模型。核对屏幕内外展示一致、GitHub 主页与 12 个项目入口保留；排查 Settings 最小化图标、Sketchbook 铅笔笔尖朝向及其他可见几何/法线问题。

先按“场景对象—几何/材质—交互—屏幕 UI”做问题清单，再研究适合现有 Three.js/R3F 的修复方式。每个问题独立给原型/对照，不借走查之名重画整个房间。

## 已确认边界

Loading page 已重新开放：本轮按用户最新意见收掉注释性文字和多余装饰，保留四叶粒子、必要的成形状态与进度提示，并沿用 Index 的白底、深色文字和四叶主题色。四叶轮的四种颜色、完整项目清单、现有四叶轮主导航逻辑仍作为锁定约束；有冲突时先报告，不自行改变。
